# Публічний профіль @maks — вигляд із maks37614/social

Джерело оформлення: `maks37614/social/src/components/TraderProfileView.tsx`
(референсна гілка `main`, commit `31369a1b13ddce3295369e8ecfbc2c9c2c99132f`).

Ціль: `https://community-stage.h00k.top/u/maks`.

## Реалізація

- Профіль `/u/maks` залишається **публічним read-only профілем поточної Community**. Його створює наявний роут `/u/:username`, який перевіряє реальне резервування username, стан акаунта та явне `publicProfileEnabled`.
- Новий фінальний стилізуючий шар `src/community/publicProfileSocialSourceClone.css` підключено після чинних профільних CSS. Він **обмежений атрибутом** `data-social-source-clone="maks"`, щоб не змінити десятки інших профілів.
- За референсом `TraderProfileView`: широкий темний банер, квадратний аватар із скругленими кутами, cyan/emerald акценти, велика біографія, горизонтальний ряд дій, блок **шести KPI**, картки реальних нагород, вкладки стіни/статей/результатів/HookChart, публікації та адаптивна мобільна сітка 2 колонки для статистики.
- Джерела відомостей лишаються **існуючими серверними API Community**: ім'я, аватар, банер, статус і біографія — тільки відкриті власником; 30-денні Win Rate/PnL — тільки дозволені агрегати Bybit linear; нагороди — тільки зареєстровані в PostgreSQL; стіна й статті — тільки публічні дописи; HookChart — тільки за дозволом автора.
- Показники `Profit Factor`, `Average R:R`, `Best trade`, `Favourite pairs`, `Friends`, `Followers` із демонстраційного `social` **не мають достовірного публічного джерела в API Community**. Їх не копіюємо як фіктивні. Для відсутніх KPI показується `—` з поясненням, а недоступні дружні зв'язки та підписники не розкриваються.
- Якщо сумарний PnL складається з кількох валют або власник не відкрив суми, замість неправдивої загальної цифри показується `—`.
- Сторонні картинки Unsplash, демонстраційні фото/пости з `mockData.ts`, бот-статус «В угоді» без джерела, вигадані нагороди та кнопки з локальним фейковим «успіхом» **не імпортуються**.

## Як надати сторінці фотографії та заповнення

Наразі на `/u/maks` публічний API повертає `avatarUrl:null`, `coverUrl:null`, порожні bio/status/awards та відсутню історію закриттів. Тому нова верстка демонструє кольоровий банер/аватар-заглушку та коректні порожні стани.

Власник `@maks` після входу в Community має завантажити власний аватар/обкладинку через налаштування публічного профілю, явно дозволити публічний показ і за бажанням увімкнути публічні нагороди або торгову статистику. Не потрібно вручну редагувати SQL чи підміняти іншого користувача.

## Вибір аватара та обкладинки власником

Після входу в Community відкрийте **Профіль → Про мене → Публічна адреса → Оформлення профілю у стилі social**:

1. **«Вибрати файл і кадрувати»** — виберіть JPEG, PNG чи WebP до 5 МіБ. Редактор дозволяє масштабування (100–300%) та налаштування горизонтального/вертикального положення. Під час натискання «Зберегти фото» завантажується лише кадрований растр: аватар 512×512, обкладинка 1440×540. Сервер додатково обробляє зображення через Sharp і видаляє EXIF.
2. **«Мої завантажені фото»** — виберіть уже наявне зображення зі своєї приватної галереї (18 елементів на сторінку). Відповідь сервера обмежена `owner_id` автентифікованого користувача. Під час вибору з галереї використовується вже оброблена фотографія без повторного кадрування, і новий файл не створюється.
3. За замовчуванням кожне нове/вибране фото — **«Лише я»**. Щоб його побачили гості на `/u/maks`, власник окремо обирає «Усі відвідувачі /u/» для аватара та/або обкладинки й має ввімкнути загальну публічність профілю. Посилання «Відкрити свою публічну сторінку» допомагає перевірити результат.
4. **«Прибрати з профілю»** скасовує прив'язку фото та переводить аудиторію у приватну, але не стирає фотографію з приватної галереї. Файл фізично залишається у медіасховищі до політики очищення/видалення акаунта.

Власний обраний аватар показується в Community-сайдбарі та редакторі дописів навіть за приватної аудиторії, оскільки ці зображення запитуються лише в контексті автентифікованого власника. У публічному API його не буде без окремого дозволу.

**Ресурси:** операції завантаження/кадрування виконуються тільки за дією користувача. Список приватних медіафайлів завантажується лише при відкритті галереї; сторінка `/u/` не має нових фонових запитів і продовжує використовувати існуючі URL зображень. Нових таблиць PostgreSQL і міграцій немає.

## Розгортання

Це зміна фронтенда **лише** `maks37614/h00k-community`. Після проходження CI на `main` вручну запустити `.github/workflows/community-staging-image.yml` на `main`, отримати реліз `community-stage-<sha12>`, на VPS перевірити SHA256, зберегти резервні копії, замінити лише Community Docker-образ через `--no-deps community`. Ні скрінер `h00k.top`, ні PostgreSQL, ні боти не перезапускаються. Нових таблиць, міграцій, WebSocket, біржових API-запитів не додається.

Візуальну тотожність на реальному пристрої потрібно перевірити після установки на VPS, до цього її не можна заявляти як перевірену.
